# Roadmap

## Native implementation status

The native rewrite is a working CPU/Apple GPU compute subset, not yet the full accepted language. The implementation record below includes historical intermediate states; this table summarizes the current position.

The latest [invocation lifecycle/ABI study](../benchmarks/results/invocation-lifecycle-2026-10-26.md) defers unused control/resource state and caches immutable process fault-injection defaults. Zero-round array/scalar entry time falls 61.5%/28.8% in matched blocks, while retaining cancellation and checked ownership. Those controls still miss the 10% C++/Rust target. Six nonempty array/closure cases remain within 4.1% across two runs; earlier [range/checkpoint results](../benchmarks/results/range-foundation-2026-10-26.md) remain historical evidence. These are scoped measurements, not a universal language performance claim.

The last main native roadmap estimate was **approximately 83% complete / 17% remaining** on 2026-10-22, before the agreed all-type Apple GPU integration was closed. That historical estimate has not been recalculated. The N4 unfinished-code tooling gate is now closed for the current native subset on macOS ARM64; remaining work includes distribution/platform qualification and native website/documentation/release work. Percentages describe coarse engineering effort, not test counts or fixed increments per feature. The main scope includes the native language/runtime, CPU and Apple Metal GPU capabilities, modules/libraries, tooling, documentation and release qualification.
[CPU compiler installation](design/native-cpu-install.md) now adds a prefix-relative compiler/runtime bundle and relocation/sanitizer acceptance. [Native release automation](design/native-releases.md) builds and qualifies CPU/editor packages on version tags, treating all SemVer prerelease identifiers (including alpha, beta and RC) as prereleases. An initial [Apple Metal compiler bundle](design/native-metal-install.md) now installs private shader tools, host headers and CPU/Metal runtimes with relocation acceptance. The [LLVM 23 migration](design/native-llvm23.md) updates the compiler, shader pipeline compatibility and release provisioning. [Standalone CPU/editor bundles](design/native-distribution-qualification.md) now include private LLVM/Clang dependencies and pass local dependency-denial tests. Hosted mixed CPU/Metal packaging, independent source-build reproducibility, Developer ID notarization and downloaded quarantine checks now pass. N5 qualification is complete for macOS 26+ ARM64 CPU/Metal, Linux x86-64 and Windows x86-64, including hosted signing/notarization, independent source rebuilds, fresh downloaded execution and physical GPU checks of the signed Mac package. FreeBSD remains deferred; Windows ThreadSanitizer is explicitly unsupported.

[NVIDIA/CUDA](native-cuda-roadmap.md), [native distributed execution](native-distributed-roadmap.md) and [C/C++ integration](native-interop-roadmap.md) have separate roadmaps and are excluded from this estimate and the main release gates. Shared foundations may support them later; their backend, public interface and deployment requirements are not main-roadmap prerequisites. The current estimate also reflects progress on variants, application errors and function values; remaining documentation, onboarding and release work still carries substantial effort.

[Machine-readable native checker diagnostics](design/native-diagnostics.md) now provide versioned success/failure responses, original module filenames and UTF-16 editor ranges. [Unsaved source checking](design/native-source-overlays.md) now adds owned replacement buffers across module/package graphs and a bounded `--stdin` root-buffer command. The [native language server](design/native-language-server.md) now publishes versioned diagnostics for full and transactional incremental open-buffer updates and rechecks imported buffers. Compiler-backed type hover and go to definition are also implemented, including captured lexical bindings and imported call targets. Bounded references across open/project import graphs now include import/re-export names and aliases, type annotations, record construction/update labels, enum cases and match patterns with distinct shorthand roles. Workspace discovery now includes eligible unopened importers, with fixed exclusions, root isolation, scan limits and explicit failure on incomplete discovery. Prepare-rename and rename now preserve explicit aliases and shorthand roles, rechecking proposed edits to reject collisions and capture. [Package-aware editor analysis](design/native-language-server.md#installed-dependencies) now follows locked private dependency scopes, with read-only installed sources and relocated editor-package qualification. Scope completion, verified native formatting and an installable VS Code client are now implemented and qualified in the real editor host. An initial [native editor-tools installation](design/native-tools-install.md) now supports prefixes and relocatable tool archives with external LLVM dependencies; CPU and initial Apple Metal compiler/runtime bundles now add private resource installation, with self-contained distribution still open.

[Apple Metal function modules](design/native-metal-modules.md) now support relative imports, aliases, re-exports, explicit local packages and native project manifests. Shared numerical helpers keep their declaring-file scope across CPU/GPU calls, and imported coordinators reuse the common scheduler/continuation plan. GPU value/type restrictions remain unchanged. Package installation and scoped editor integration are now implemented, and [installed numerical libraries](design/native-metal-install.md#installed-numerical-libraries) now qualify private-version CPU-worker/GPU execution. Platform/distribution qualification is complete for the agreed macOS/Metal, Linux and Windows scope; documentation, onboarding and release preparation remain in N6.

[Fixed GPU tensor signatures](design/native-gpu-fixed-shapes.md) now preserve fixed, dynamic and mixed extent contracts through imported numerical helpers, including parameter, binding and result checks before dispatch. They reuse the existing shaders and do not widen GPU element-type or operation coverage.

[GPU numerical forwarding](design/native-gpu-forwarding.md) now allows bindings and imported helpers around one reduction or matrix operation, preserving reordered/repeated operands, shape contracts and existing numerical kernels. General numerical graph composition remains incomplete.

## Platform qualification order

Qualify macOS ARM64 with Metal first. CPU toolchain/runtime qualification for Windows x86-64, Linux and then FreeBSD remains planned; other BSD systems need individual qualification. NVIDIA GPU support on Windows and Linux belongs to the [separate CUDA roadmap](native-cuda-roadmap.md) and does not block the main roadmap. Other GPU backends, including OpenCL, follow concrete hardware/deployment needs and are not prerequisites for the first native release. These are planned targets, not a claim of current support.

## Advanced GPU interoperability — planned follow-up

These are two separate future workstreams, deferred until after the current generated-kernel integration baseline. Neither expands the immediate core queue or adds a prerequisite to the current native release gates. Public APIs and syntax are not accepted yet.

### User-supplied compute shaders and kernels

Let applications supply custom GPU computation for specialized operations not expressed by the supported Kalandra subset. Start with Apple Metal; backend-specific CUDA artifacts follow the separate NVIDIA roadmap.

Define typed tensor/scalar bindings, output shapes, device requirements, dispatch configuration, source versus precompiled artifact loading and packaging. Integrate immutable input ownership, fresh result storage, retained resources through command completion, explicit transfers, budgets and existing task error/cancellation settlement. Cancellation must not imply that an already submitted GPU command can be forcibly stopped.

Specify the foreign-code safety and numerical boundary: reflection/layout checks alone cannot prove an arbitrary shader's memory accesses, immutability or arithmetic semantics. Do not silently grant user-supplied shaders the guarantees of compiler-generated kernels.

### External GPU compute libraries

Let applications reuse existing optimized operations through library adapters, separately from loading custom shaders. Candidate integrations include Metal Performance Shaders on Apple and cuBLAS under the separate NVIDIA roadmap; these are examples, not selected dependencies or implementation commitments.

Define supported operations, tensor formats/layouts, device compatibility, dependency packaging and task completion integration. Preserve Kalandra ownership and explicit transfer rules. Specify numerical compatibility per operation; a library operation must not silently replace a strict language operation when rounding, reduction order or other semantics differ. Evaluate usefulness and implementation scope before selecting the first adapter. Shared resource/dispatch foundations may be reusable, but library adapters and custom-kernel loading have distinct interfaces and qualification work.

## Optimization

- **Deep tensor-choice compile time:** profile and bound MLIR One-Shot Bufferize alias analysis for long tensor-valued `if`/`else` chains in the CPU shadow functions used for GPU admission. A linear 40-leaf choice after summing 40 dynamic tensor parameters exposes pathological scaling; the 40-source qualification uses a single choice over two tensor expressions. GPU source arity and this compile-time issue are separate concerns.
- **Conditional GPU graph bindings:** investigate projected direct bindings for small scalar-control graphs. The current [argument-buffer path](design/native-gpu-scalar-control.md#strict-lowering) preserves declared resources when optimization removes a predicate or identical arm. Derive any replacement from the lowered shader interface and preserve exact binding indices, capture budgets and failure/lifetime behavior.

- **Parallel-map scheduling:** tune task/chunk granularity, bounded window width and capacity-aware admission; reduce repeated capture copying and avoid whole-batch straggler stalls. Preserve ordered results, typed failures, cooperative cancellation and resource accounting. The initial [CPU implementation](design/native-parallel-map.md) uses up to eight element tasks per batch.

- **Trusted immutable String query paths:** avoid repeated full UTF-8 validation when compiler/runtime provenance proves a value was already validated. Preserve validation at untrusted descriptor boundaries, cooperative cancellation, exact counts and owner lifetimes. The initial [length queries](design/strings.md#scalar-and-byte-lengths) validate on every call; byte-count retrieval itself is constant time.

Complete missing native functionality before taking on these performance improvements. The current copying reshape implementation remains the baseline; immutable value semantics allow storage sharing but do not require it.

- **Shared-storage tensor reshapes and collection conversions:** avoid copying elements when the source layout is compatible with the requested logical row-major reshape. Retain managed backing for the result's full lifetime, including helper returns, worker captures/results and repeated awaits. Keep an ordered-copy fallback when layout or borrowed-storage lifetime prevents safe sharing. Qualify actual pointer sharing, backing lifetime, empty/rank-zero tensors, offsets, cancellation and failure cleanup before enabling the optimization. Apply the same lifetime qualification to [tensor-to-array construction](design/tensor-array.md#ordering-and-ownership) and [array slices](design/array-slicing.md#storage-and-execution-scope), including interior offsets and retained String/record child storage. Include the [numeric indirect-call descriptor adapters](design/native-function-values.md#collection-parameters-and-results), which currently pack/unpack copies at each call boundary. Preserve checked shape validation, borrowed/strided input ordering, invocation isolation, retained worker data and allocation-failure cleanup when eliminating those copies. See the [current reshape implementation](design/tensor-reshape.md#ordering-errors-and-memory).

- **Record collection storage:** replace construction/read copies with shared immutable backing where safe, and reclaim temporary field storage at last use instead of waiting for invocation settlement. Preserve worker retention, shape checks, repeated-await snapshots and failure cleanup.

- **Resumable callable dispatch:** compact finite-target continuation specialization, reduce repeated validated environment copies and qualify a bounded continuation stack before supporting recursive coordinating function values. Preserve runtime target selection, typed errors, cancellation, provenance and ownership. See [CPU resumable callables](design/native-resumable-callables.md).

- **Closure environments:** eliminate or specialize capture allocations where proven safe, share immutable numeric backing instead of descriptor packing copies, and reclaim environments and transitive captures after their last use. Preserve distinct creator environments, nested captures, checked failures and invocation/worker lifetimes. The initial implementation keeps managed environments until invocation settlement.

- **Recursive execution:** the [native call convention](design/checked-call-optimization.md) removes the 128-call cap and uses native internal returns, physical stack admission and eligible guaranteed tail calls. The refreshed production Darwin ARM64 hybrid-cancellation recursion suite meets the Rust/C++ 10% target in all 30 non-empty comparisons. [Native synchronous task subgraphs, local closure promotion and rank-one array tail loops](../benchmarks/results/task-native-optimization-2026-10-26.md) now remove per-call task continuations and bound eligible intermediate-array lifetimes. Paired measurements reduce short closure time by about 71% and 256-step array time by about 22%; complete 256-step task scopes improve about 52% with one worker and 78–80% with eight. The expanded Rust/C++ comparison still exposes short-workload, allocation/status-check and captured-arithmetic gaps; it does not establish general language or Linux/Windows parity. Continue expected-error callable-frame specialization, tensor ownership/copy analysis, checked-entry cost and task-runtime lifetime reuse. Continue qualification of fallible tail paths and recursive array ownership traversal; heap-stack traversal and more precise stack estimation remain work. Preserve source errors, cancellation, owned outcomes and balanced runtime boundaries.

- **Synchronous callable frames:** specialize direct targets and reuse or eliminate temporary frames where proven safe. Expected-error/control-flow function values and direct control-flow map callbacks currently allocate a checked invocation-owned frame per call, which can accumulate across large maps. Preserve evaluation order, typed outcomes, original fault locations, cancellation, retained payload lifetimes and allocation-failure cleanup. This optimization does not require source allocator annotations.

- **Compact enum storage and dispatch:** replace the first [fully initialized tagged aggregate](design/native-enums.md) with a compact active-payload representation and scalable switch dispatch. Preserve nominal identity, source evaluation order, exhaustive matching and managed payload lifetimes through workers. The current compiler depth budgets remain explicit until dispatch is qualified. This is an optimization, not a change to source variant semantics or a public ABI promise.

**GPU graph stage fusion:** after correctness qualification, combine compatible
adjacent arithmetic stages to reduce command and intermediate-storage overhead.
Preserve source operand order, strict float32 rounding and final-use ownership;
this is optimization work rather than new source syntax.

## Native implementation record

**Design and implementation record:** design an immutable, memory-safe language for native CPU, GPU, and distributed execution. The [core syntax and immutable value behavior](design/core.md) are accepted as the starting point, with explicit numeric families replacing `Number`. The [memory design](design/memory.md) selects automatic lifetimes and compiler-chosen allocation without an allocation-scope keyword. The [numeric types and arithmetic rules](design/numbers.md) are accepted. The [errors and effects direction](design/errors.md) is accepted. [Resources and task lifetimes](design/execution.md) are accepted, including inline spawn/await. [Variants and error payloads](design/variants.md) are accepted. [Tensor types and shapes](design/tensors.md) are accepted. [Placement, transfers, and bulk tasks](design/placement.md) are accepted in direction. The [complete CPU/GPU/remote application example](design/compute-example.md) is accepted as the integration direction. The [first native CPU compiler milestone](design/cpu-milestone.md) is accepted as the implementation sequence. Its [pinned MLIR/LLVM toolchain proof](../native/toolchain-proof/README.md) passes on macOS ARM64; the [handwritten C++23 lexer/parser](design/frontend.md) now parses the projection fixture with diagnostics and sanitizer-tested limits. [Name resolution and typed IR](design/semantics.md) now check the projection fixture with literal typing, symbol resolution, shape facts/guards, and strict numeric metadata. [Native MLIR/LLVM lowering](design/native-codegen.md) now compiles the source into a standalone executable producing 163. The first sequential float32 CPU milestone and conformance sweep now pass, including 1,029 runtime shape/content cases per build variant, nested/shared tensor lifetimes, allocation-failure cleanup, evaluation order, and a fresh source-only build. The [native local-task contract](design/native-tasks.md) now specifies ownership, explicit status propagation, resumable waits, bounded scheduling, and failure/cancellation settlement. Checked invocation contexts and managed tensor ownership now replace process-global cleanup on source-generated paths; isolated checked faults preserve sibling/parent data and allow another invocation to continue. The single-worker task core now implements resumable waits, bounded admission, cached immutable outcomes, and group cancellation/settlement using synthetic native entries. The first source task subset now lowers parallel/spawn/await and TaskError propagation to native LLVM continuations, retaining the MLIR tensor kernels. Native TaskError recovery now implements catch, exhaustive built-in matching, typed fields, and handler-local try/fail propagation. Bounded multi-worker CPU execution and cooperative loop cancellation now pass their conformance tests. The native conformance suites pass, including debug, optimized, ASan/UBSan, and separate TSan coverage of runtime and generated code. The [native CPU scaling baseline](../benchmarks/results/native-cpu-2026-10-15.md) now measures warmed kernel throughput, scheduling overhead, and allocation counts. Matrix reduction scratch reuse now passes the same numerical, failure, and cancellation gates, with [before/after measurements](../benchmarks/results/native-cpu-2026-10-15-scratch.md). The [scheduler profile](../benchmarks/results/native-scheduler-2026-10-15.md) now separates table-capacity costs from multi-worker coordination, using uninstrumented phase timings and separate diagnostic probes. Unnecessary idle-worker notifications and empty-drain activation are now removed, with [before/after measurements](../benchmarks/results/native-scheduler-2026-10-15-wakeups.md), held-lease wakeup regressions, and unchanged numerical conformance. Worker/controller wait channels are now separated, with targeted active notifications and [paired measurements](../benchmarks/results/native-scheduler-2026-10-15-targeted.md). Ready-table sweeps are now replaced with [bounded runnable tracking](../benchmarks/results/native-scheduler-2026-10-15-runnable.md), retaining narrow-queue nested spawning and deferred continuation progress. Maintenance now uses [bounded occupancy indexes](../benchmarks/results/native-scheduler-2026-10-15-maintenance.md) for unfinished tasks and live records/groups, preserving sparse high slots, deep nested waits, and concurrent cleanup. The [task-maintenance fast path](../benchmarks/results/native-scheduler-2026-10-15-dense.md) now skips primary task scans when no waiter or settlement exists, preserving group progress and cleanup leases. The [four-column SIMD comparison](../benchmarks/results/native-cpu-2026-10-15-simd.md) now records the first CPU microtile optimization, with separately rounded lane arithmetic, scalar tails, 1,617 aggregate cases, and 705 per-cell/shared cases. The [37-shape comparison](../benchmarks/results/native-shapes-2026-10-15.md) identified narrow-column and tail costs. Narrow dispatch and two-lane output/tail specialization are now implemented, with [paired shape measurements](../benchmarks/results/native-shapes-2026-10-15-pairs.md), 717 per-cell/shared cases, and extended cancellation/deadline coverage. The [cache-layout evaluation](../benchmarks/results/native-cache-2026-10-15.md) now measures strict C++ row/column and contraction-block prototypes against generated code and a library reference. The [MLIR 4×16/K256 port](../benchmarks/results/native-mlir-blocking-2026-10-15.md) now implements full/edge tiles in a private kernel, preserving narrow paths, checked storage and per-lane arithmetic, with 3,727 per-cell/shared cases, 506 actual allocation-payload cases, and renewed concurrency/cancellation/sanitizer checks. The optional [Apple GPU toolchain proof](../native/metal-proof/README.md) now executes handwritten MLIR GPU kernels through SPIR-V/SPIRV-Cross/Metal on an M2 Max. Finite, tail, and immutable-input checks pass, but IEEE edge probes expose subnormal and bridge signed-zero differences; strict float32 GPU admission remains unavailable. The [Apple GPU backend contract](design/apple-gpu.md) scopes device/storage tasks, completion, cancellation, numerical compatibility, and subsequent source lowering. The optional [native Metal transfer runtime](../native/metal/README.md) now adds managed host/device backings, checked uploads/downloads, nested transfer tasks, and scheduler external-completion leases with cancellation-safe cleanup, byte/command budgets, and failure injection. Host ASan/UBSan and separate TSan coverage exercise the bridge and scheduler. A [strict binary32 integer MLIR lowering](design/strict-gpu-float32.md) now verifies scalar float32 add/multiply and their separately rounded composition against APFloat and CPU hardware on CPU LLVM and Metal, with IEEE edge/stratified/random conformance and artifact/rejection checks. Direct hardware float32 remains incompatible; managed compute-task integration now passes through a checked private dynamic-array kernel ABI, including nested tasks, explicit transfers, IEEE differential conformance, cancellation, budgets, and failure cleanup. An optional source compiler now lowers a bounded rank-one float32 placement/transfer program into C++ supervisor continuations and source-generated strict GPU MLIR, with a standalone executable/shader build driver, transitive helper/constant checks, repeated calls, source diagnostics, and cancellation/failure conformance. The common compiler now selects the linked Metal backend with `--target metal`; retained CPU allocation leases and checked MLIR descriptor import/export pass CPU→GPU→compiled-CPU conformance. Common mixed-source typed IR, richer dynamic entry parameters, other arithmetic, general tensor kernels, and performance qualification remain gated. NVIDIA/CUDA on Windows follows Apple support under its [separate roadmap](native-cuda-roadmap.md), outside the main completion estimate and release gates. The native build uses CMake/Ninja/CTest with direct LLVM/MLIR C++ integration and no Bun/Node requirement. The original hand-written IR proof remains a separate backend reference; the source compiler has its own executable conformance tests. Concrete residency, deployment, and runtime API contracts remain tracked before their implementation. These documents describe the fresh design; their syntax is not implemented in the released compiler. Ordinary CPU and GPU functions now coexist in one source program: checked MLIR/LLVM CPU calls can consume explicit downloads, with float32 scalar results, allocation-failure cleanup, and separate sanitizer variants. CPU tensor results now retain immutable backing across CPU calls and GPU transfers; runtime guards check shapes that are unknown statically. Shared CPU/GPU helper compilation now preserves original tensor/scalar types in one checked function IR, with elementwise CPU loops, GPU lane lowering, propagated shape constraints, and differential numerical conformance. A common placement-aware task/residency IR remains subsequent work. Elementwise GPU entries now use signature-sized owned captures and compact reflected bindings for contributing rank-one/rank-two float32 tensors; unused arguments retain their logical contracts without consuming input bindings. See [entry parameter scope](design/apple-gpu.md#unused-tensor-arguments-and-shape-obligations).

Native GPU follow-up: [GPU-ABI-001](design/apple-gpu.md#tracked-follow-up-general-gpu-parameter-layouts-gpu-abi-001) now has [signature-sized owned captures](design/apple-gpu.md#signature-sized-gpu-captures), replacing the fixed two-tensor/eight-scalar storage. Three tensors with twelve interleaved scalars and the 29-input Metal direct-binding boundary are qualified; capture storage has a separate byte budget. [Unused tensor arguments and operation-derived shape obligations](design/apple-gpu.md#unused-tensor-arguments-and-shape-obligations) are now implemented for the current subset, including a 40-tensor logical signature with one physical input. [Tier 2 argument buffers](design/apple-gpu.md#tier-2-argument-buffers-for-large-gpu-calls) now handle more than 29 contributing inputs without copying tensor payloads; 30-input and 40-input source programs are qualified. Broader types and tensor operations remain open. Backend resource limits are not language parameter limits. The first [rank-one GPU reduction](design/apple-gpu.md#rank-one-gpu-reductions) now implements `reduceSum` with scalar task results, the accepted deterministic tree and four-byte readback. The first [rank-two GPU matmul](design/apple-gpu.md#rank-two-gpu-matrix-multiplication) now preserves separately rounded products and the fixed tree, with matrix support in the mixed CPU/GPU source bridge. The [initial CPU/Metal performance baseline](../benchmarks/results/native-gpu-2026-10-15.md) now separates device command, resident task and transfer costs. The [strict normalization optimization](../benchmarks/results/native-gpu-2026-10-15-normalization.md) now removes per-bit integer loops, improving 256-square GPU command latency by 3.09× while preserving strict rounding and the accepted tensor tree. CPU still wins on tested matmul shapes. The [GPU tiling study](../benchmarks/results/native-gpu-2026-10-15-tiling.md) now qualifies cooperative/register candidates and shows shape-dependent benefits and regressions. The [49-shape crossover and managed selection](../benchmarks/results/native-gpu-2026-10-15-selection.md) now enable conservative two-row/quad dispatch on Apple M2 Max, preserving scalar GPU execution outside the measured profile and on other devices. Numerical, failure/lifetime and repeated resident/transfer measurements qualify the integration. [Reduction scratch reuse](../benchmarks/results/native-gpu-2026-10-15-reduction-reuse.md) now retains two alternating outputs while preserving the fixed tree and invocation isolation. [Rank-two GPU reductions](design/apple-gpu.md#rank-two-gpu-reductions) now keep matmul → reduceSum intermediates resident, returning only the final scalar with the same strict row-major tree. [Rank-two elementwise GPU helpers](design/apple-gpu.md#rank-two-gpu-elementwise-helpers) now support strict scaling/addition and transitive helpers with complete axis guards, enabling a resident matmul → adjust → reduceSum pipeline. [Serial reduction dispatch batching](../benchmarks/results/native-gpu-2026-10-16-reduction-batching.md) now uses one compute encoder for all levels with unchanged strict arithmetic, memory and lifecycle guarantees; warm timings are roughly flat. Apple-family reduction count words now share one immutable parameter buffer, cutting temporary Metal buffer objects from 23 to 4 for a million-element sum without changing requested payload bytes; [matched warm measurements](../benchmarks/results/native-gpu-2026-10-16-reduction-parameters.md) record lower managed-call latency on M2 Max. Strict tensor subtraction and scalar negation now share the CPU/GPU lowering, with [APFloat, lifecycle and source checks](design/apple-gpu.md#strict-tensor-subtraction-and-scalar-negation). [Whole-tensor unary negation](design/apple-gpu.md#whole-tensor-unary-arithmetic) now preserves exact sign-bit behavior through CPU functions, CPU tasks and GPU helpers, with shape-preserving typed IR. [Strict tensor division](design/apple-gpu.md#strict-tensor-division) now works with either scalar operand order and transitive reciprocal helpers. [Inline CPU expressions](design/apple-gpu.md#inline-cpu-expressions-in-mixed-programs) now compose arithmetic, reductions and matmul directly in mixed-program main, through shared checked CPU kernels. [CPU tasks in mixed programs](design/apple-gpu.md#cpu-tasks-in-mixed-programs) now support unplaced and explicit/aliased CPU spawn, owned scalar/tensor captures, and CPU↔GPU task pipelines on the bounded scheduler. Broader value types and asynchronous helper bodies remain ahead; subsequent mixed-program progress is recorded below.

**Mixed CPU/GPU task progress:** [Nested parallel scopes](design/apple-gpu.md#nested-parallel-scopes-in-mixed-programs) now return completed values across lexical groups in `main`, retaining explicit residency and bounded scheduler cleanup. [Scoped TaskError recovery](design/apple-gpu.md#scoped-taskerror-recovery-in-mixed-programs) now handles settled group results, exhaustive matching and handler-local propagation. [Shared placement-aware frontend IR](design/placement-ir.md) now checks selectors, transfers, captures and residency before Metal artifact publication. The [IR-driven supervisor](design/placement-ir.md#ir-driven-supervisor-continuations) now lowers mixed-program control flow from checked values and resolved symbols. The [common continuation planner](design/continuations.md) now drives both CPU task lowering and the Metal supervisor. [Direct resumable helpers](design/continuations.md#resumable-mixed-helper-bodies) now coordinate CPU/GPU tasks, own scopes and return completed host values through transitive calls. [Independently scheduled helper children](design/continuations.md#independently-scheduled-mixed-helpers) now own captures, frames, nested work and completed results on the bounded scheduler. [Shared numeric descriptions](design/numbers.md#shared-numeric-descriptions-in-the-native-implementation) now carry concrete identity, family and width through typed IR and checked storage sizes, with float32-only arithmetic gates. [Element-aware CPU storage and adapters](design/numbers.md#element-aware-cpu-runtime-storage-and-adapters) now validate typed tensor leases/copies and distinct scalar task layouts without changing float32 arithmetic. [Checked CPU int32 scalars](design/numbers.md#checked-cpu-int32-scalar-arithmetic) now support contextual literals, ordinary functions and exact executable results, with compile-time/runtime overflow and division checks. [Int32 CPU task continuations](design/numbers.md#int32-cpu-task-captures-and-results) now support typed captures/results, nested workers, mixed numeric packets and supervised arithmetic faults through the same checked MLIR lowering. [Synchronous int32 CPU tensors](design/numbers.md#checked-cpu-int32-tensor-literals-and-elementwise-operations) now support typed literals, ranked elementwise operators and checked native interfaces. [Int32 tensor worker handoff](design/numbers.md#int32-tensor-captures-and-results-in-cpu-tasks) now preserves element-aware captures/results and backing lifetimes across nested tasks, cached awaits and failure recovery. [Checked int32 CPU reduceSum](design/numbers.md#checked-cpu-int32-reducesum) now preserves the balanced-adjacent tree, checks every addition and integrates worker fault recovery. [Checked int32 CPU matmul](design/numbers.md#checked-cpu-int32-matmul) now checks each product and tree sum, returns retained matrices through nested workers and supports supervised Arithmetic recovery. [Checked CPU uint32 scalars](design/numbers.md#checked-cpu-uint32-scalar-arithmetic) now support exact constants/CLI values, unsigned MLIR operations, distinct task layouts and nested Arithmetic recovery. [Synchronous uint32 CPU tensors](design/numbers.md#checked-cpu-uint32-tensor-literals-and-elementwise-operations) now support exact literals, unsigned elementwise checks, scalar lifting and checked native interfaces. [Uint32 tensor worker handoff](design/numbers.md#uint32-tensor-captures-and-results-in-cpu-tasks) now preserves distinct unsigned/signed/float layouts and retained backing across nested tasks, cached awaits and recovery. [Checked CPU uint32 reduceSum](design/numbers.md#checked-cpu-uint32-reducesum) now reuses the adjacent reduction tree and shared integer conformance harness, with unsigned overflow checks and worker fault recovery. [Checked CPU uint32 matmul](design/numbers.md#checked-cpu-uint32-matmul) now reuses integer matrix loops, checked unsigned products/tree sums and retained worker results, with shared signed/unsigned conformance. [Checked CPU int64 scalars](design/numbers.md#checked-cpu-int64-scalar-arithmetic) now support the int alias, default whole-number inference, exact CLI values, width-aware checked lowering and mixed-width worker captures/results. [Checked CPU uint64 scalars](design/numbers.md#checked-cpu-uint64-scalar-arithmetic) now support the uint alias, full-range constants/CLI values, width-aware unsigned lowering and five-family worker captures/results. Int64/uint64 tensors, further widths, GPU integer arithmetic, conversions, broader values and modules remain gaps.

**Deferred lower-level access:** [LL-001](design/placement.md#deferred-direct-execution-and-memory-controls-ll-001) tracks immutable updates and more direct execution controls (numeric array/tensor scalar reads now have checked implementations), explicit SIMD/vector operations, custom GPU kernels and finer coordination/memory controls. These are later design work; syntax and unsafe facilities are not accepted yet.

**Native library embedding:** support compiling Kalandra functions to object files and static/shared libraries that C++ and other native hosts can link. Define a stable C ABI and generated headers first, including scalar/tensor representation, checked failures, retained output ownership, runtime initialization/shutdown and task/device lifecycle. Optional C++ wrappers can make that interface easier to use. Private compiler test entry points are not a public ABI commitment. This is tracked native tooling work, not currently supported library packaging.

**Native distributed execution gate:** complete a separate design review of contracts, deployment, transport, cancellation and remote data lifetimes before implementing distributed execution.

**Numerical type expansion:** reuse the scheduler, task/error control flow, ownership, placement and shape machinery. Shared element-type descriptions now replace implied numeric identity and duplicated storage widths. CPU runtime descriptors, retention/copy adapters and scalar task layouts are now element-aware. Additional source arithmetic still requires per-type compiler lowering and qualification before its capability gate can be enabled. Each type still needs its own arithmetic semantics, CPU/GPU capability checks and numerical conformance; floating-point bit algorithms are format-specific.
