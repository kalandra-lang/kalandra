# Kalandra 0.99.2 — CUDA and Vulkan

Kalandra 0.99.2 adds Linux CUDA and Vulkan compiler distributions, experimental Windows CUDA/Vulkan distributions, and native call correctness fixes. This is the GPU-delivery checkpoint before the next language-design work. Existing source programs retain the immutable language model; mutation and loop proposals are not part of this release.

Changes since [0.99.1](https://github.com/kalandra-lang/kalandra/releases/tag/v0.99.1):

## GPU programs in one language

The same Kalandra placement, transfer and task APIs now target Apple Metal, Vulkan and CUDA. Compile with `--target metal`, `--target vulkan` or `--target cuda` using a compiler package that includes that backend. A CPU-only package does not acquire a GPU backend from the flag alone.

Linux x86-64 Vulkan execution was qualified on NVIDIA RTX 5090 and Intel ARL; CUDA execution was qualified on RTX 5090. This is a named device/driver qualification matrix, not a claim of support for every Vulkan or NVIDIA GPU. ARM64 Linux and Raspberry Pi remain CPU targets; VideoCore acceleration is not included. macOS continues to use native Metal on Apple silicon with macOS 26 or later.

The GPU numerical subset supports ten numeric storage types, tensor ranks zero through eight, matrix operations, reductions, resident numerical composition and supported function/control flow. Hardware arithmetic is the default where supported. Software arithmetic and hardware-with-software-fallback remain explicit policies. Device limitations are diagnosed; missing resources and driver faults do not trigger silent CPU or numerical fallback.

Matrix products default to `--matmul-policy fixed-tree`. Explicit `optimized` permits full-float32 FMA and a different accumulation order. Production kernels use reviewed permissively licensed implementations, including MIT ggml-derived Vulkan code and BSD-3-Clause CUTLASS CUDA code. No cuBLAS/Accelerate/MPSGraph substitution, TF32 or half-precision shortcut is enabled by that policy. GPU results should be checked using the documented numerical contract rather than assuming bitwise equivalence between policies.

## Windows GPU support is experimental

Windows x86-64 and ARM64 CUDA/Vulkan compiler packages pass native build and installed-package checks: complete GPU source compilation, CPU execution, relocation, secure driver lookup, PE dependency audits, resource failures and reproducible packaging.

**Physical Windows GPU execution, numerical correctness, cancellation behavior and performance are not yet qualified.** ARM64 compiler availability does not imply that NVIDIA supplies a compatible ARM64 CUDA driver. [Issue #276](https://github.com/kalandra-lang/kalandra/issues/276) tracks Windows VM passthrough setup and hardware testing. No software GPU or CPU substitute counts as this qualification.

## Downloads and installation

Download from this GitHub release's **Assets** section, verify the SHA-256 sidecar, and retain the complete extracted toolchain directory.

| Build host / GPU backend | Standalone archive |
| --- | --- |
| Linux x86-64 / CUDA | `kalandra-native-cuda-standalone-linux-x86_64.tar.gz` |
| Linux x86-64 / Vulkan | `kalandra-native-vulkan-standalone-linux-x86_64.tar.gz` |
| Windows x86-64 / CUDA, experimental | `kalandra-native-cuda-standalone-windows-x86_64.tar.gz` |
| Windows ARM64 / CUDA, experimental | `kalandra-native-cuda-standalone-windows-arm64.tar.gz` |
| Windows x86-64 / Vulkan, experimental | `kalandra-native-vulkan-standalone-windows-x86_64.tar.gz` |
| Windows ARM64 / Vulkan, experimental | `kalandra-native-vulkan-standalone-windows-arm64.tar.gz` |

The signed, notarized and stapled macOS Metal DMG remains `kalandra-native-metal-standalone.dmg`. CPU-only and editor-only distributions remain available. GPU host packages also include runtime data and private host linkers for all five CPU destinations; cross-compilation covers CPU programs, not cross-platform GPU application builds.

Linux compiler use requires system C++23 development headers; GPU applications require the compatible system driver/loader. CUDA requires an NVIDIA driver supporting PTX 9.2; installed CUDA compiler packages do not require the CUDA toolkit, NVRTC or cuBLAS. Windows compilation requires matching Visual Studio C++ Build Tools and Windows SDK in a developer command prompt. No system SDK or driver library is bundled. Keep generated `program` / `program.exe` with its entire PTX/SPIR-V resource directory.

`kalandra --version` and the native language server report **0.99.2**. Install `kalandra-native.vsix` from the same release; its independent extension version remains 0.1.0. Existing editor configuration continues to work. See [installation](https://kalandra.dev/docs/installation), [GPU computing](https://kalandra.dev/docs/gpu) and [editor setup](https://kalandra.dev/docs/tooling).

## Correctness and resource safety

Windows CPU stack admission now accounts for the peak outgoing scalar argument packet instead of summing sequential call packets. The 16 KiB frame allowance and 128 KiB runtime reserve are unchanged. Large ARM64 stack-passed signatures use a conservative caller-pop convention, fixing O0 crashes on Linux and Windows; register-only fast calls remain enabled. Matching wide signatures remain eligible for guaranteed tail calls, while differing wide signatures may consume stack. The ABI change is documented in the compiler design notes.

Qualification includes a forty-tensor-argument regression at O0/O2, all 20 directed CPU platform pairs, numerical/reference checks, ownership and cancellation tests, installed archive checks and reproducibility gates. Cancellation remains cooperative at established CPU checkpoints and completed GPU stages; submitted device resources remain alive until confirmed completion. It does not reset the GPU or interrupt unrelated applications.

Windows GPU sanitizer profiles and cross-target GPU builds remain unsupported. Distributed compute, user-written low-level kernels and the planned local-mutation language changes are not included.
