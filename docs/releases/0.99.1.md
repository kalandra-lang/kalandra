# Kalandra 0.99.1 — ARM64 and cross-compilation

Kalandra 0.99.1 expands native CPU development to Linux ARM64 and Windows ARM64, and lets one host compiler produce applications for all five supported CPU platforms. The macOS distribution continues to provide mixed CPU/Metal development on Apple silicon.

These are the changes since [0.99.0](https://github.com/kalandra-lang/kalandra/releases/tag/v0.99.0).

## Linux ARM64 and Raspberry Pi

The compiler, language server and generated CPU applications now run natively on Linux ARM64. Download `kalandra-native-cpu-standalone-linux-arm64.tar.gz` for Ubuntu 24.04 or a compatible ARM64 system with glibc 2.39 or newer.

Modern Raspberry Pi boards are supported with a 64-bit OS: Pi 3, Pi 4, Pi 5 and Zero 2 W. Use **64-bit Raspberry Pi OS Trixie (Debian 13)**. Bookworm's glibc is too old for this distribution. This is ARMv8-A CPU support; VideoCore GPU execution and 32-bit Pi systems are not included. CI qualifies the package on native ARM64 runners and in official Raspberry Pi OS userspace; physical Pi boards, firmware and kernel variants were not tested.

## Windows ARM64

Download `kalandra-native-cpu-standalone-windows-arm64.tar.gz` for Windows 11 ARM64. The compiler, editor tools, language server and generated applications run natively rather than through x86-64 emulation.

Install Visual Studio 2026 ARM64 C++ Build Tools and the Windows SDK, and compile from an ARM64-targeting developer shell. The pinned ARM64 LLVM distribution does not provide ASan, UBSan or TSan runtimes: sanitizer options fail explicitly. Normal and optimized builds retain Kalandra's arithmetic, bounds, ownership and task checks.

## One compiler download, five CPU destinations

Each standalone CPU or mixed CPU/Metal package includes the five CPU runtime datasets and host-native ELF, PE/COFF and Mach-O linkers. Download the package for the machine **running the compiler**, then select the destination:

| `--platform` | Destination |
| --- | --- |
| `linux-x86_64` | Linux x86-64 |
| `linux-arm64` | Linux ARM64, including supported 64-bit Raspberry Pi systems |
| `windows-x86_64` | Windows x86-64 |
| `windows-arm64` | Windows ARM64 |
| `macos-arm64` | macOS 26+ on Apple silicon |

For example, compile an existing CPU program for macOS from any supported host:

```sh
kalandra main.k --platform macos-arm64 -O2 -o program-macos
```

No Apple SDK or separate LLVM installation is required for this path. Kalandra ships its own link-only system import declarations, validated against macOS 26 exports; no Apple SDK headers or library implementations are redistributed. The executable has an ad hoc signature; Developer ID signing and notarization remain separate steps when distributing your own applications.

Linux destinations still require their GNU development libraries and startup objects. Windows destinations still require their Windows SDK and MSVC CRT link libraries. These system development libraries are **not bundled**. Select them using `--sysroot`, `--gcc-directory` and repeated `--library-directory` flags, or a reusable `--toolchain profile.json`. See the [cross-compilation guide](https://kalandra.dev/docs/cross-compilation) for complete Linux, Windows and macOS examples.

Only the selected runtime is linked into an application. Bundling the alternatives increases download and disk size without changing execution speed or introducing emulation.

## ABI and safety improvements

The compiler now consistently uses the destination ABI for data layouts, record and closure allocation, stack-pointer access, task lowering and private calling conventions. Invocation storage has checked layouts across all five CPU ABIs. Runtime versions, checksums, object architectures and macOS deployment compatibility are validated before linking. Invalid toolchain configurations and failed links preserve existing output files.

All **20 cross-compilation directions** passed **63 programs each** on native destination runners: **1,260 executions** covering all ten numeric types, tensor operations, functions, recursion, owned values, tasks, cancellation and fault behavior. Each executable was reproduced independently; all five host packages and their shared runtime-data archive were also independently assembled with identical bytes. This is correctness and portability qualification, not a new performance benchmark.

## Installation and editor setup

Choose the package matching your build host from this release's Assets:

- **macOS 26+ Apple silicon:** `kalandra-native-metal-standalone.dmg` for mixed CPU/GPU development; `kalandra-native-cpu-standalone.dmg` for CPU-only development. Standalone DMGs are Developer ID signed, notarized and stapled. Copy the complete toolchain directory out of the DMG before ejecting it.
- **Linux:** `kalandra-native-cpu-standalone-linux-x86_64.tar.gz` or `kalandra-native-cpu-standalone-linux-arm64.tar.gz`.
- **Windows 11:** `kalandra-native-cpu-standalone-windows-x86_64.tar.gz` or `kalandra-native-cpu-standalone-windows-arm64.tar.gz`.

Verify the SHA-256 sidecar, extract or copy the complete directory, and add its `bin` directory to `PATH`. Keep its `bin`, `lib`, `libexec` and `share` resources together. `kalandra --version` reports `0.99.1`.

Download `kalandra-native.vsix` from the same release, use VS Code's **Extensions: Install from VSIX**, and select the installed `kalandra-lsp` in **Kalandra Native: Server Path**. The extension retains its independent version, 0.1.0; the native server reports 0.99.1. Other LSP editors can launch that same server over standard input/output. No Node.js or npm installation is needed for the native tools or installed editor client.

See [installation](https://kalandra.dev/docs/installation) and [editor setup](https://kalandra.dev/docs/tooling) for platform prerequisites. Native compilation defaults retain their existing system-toolchain requirements; the explicit cross-platform path uses the bundled host linker and selected runtime.

## Scope and compatibility

This release does not change Kalandra's numerical or cancellation contracts. Cross-compilation currently supports the CPU backend; it does not cross-compile Metal kernels, provide CUDA/Vulkan execution, or qualify cross-target sanitizer combinations. macOS x86-64, 32-bit targets, Windows ARM64 sanitizers and FreeBSD distribution qualification are not included. Existing macOS Metal requirements remain Xcode 26.2 and the pinned Metal Toolchain component.
