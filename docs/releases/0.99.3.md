# Kalandra 0.99.3 — language and standard-library foundations

Kalandra 0.99.3 completes the core language milestone: checked local mutation, expression-valued control flow, lazy generators, explicit returns, static generics and traits, practical host I/O, and broader GPU language support. It includes the changes merged since [0.99.2](https://github.com/kalandra-lang/kalandra/releases/tag/v0.99.2).

**This release changes source syntax and application entry behavior.** Read the migration section before rebuilding older programs. Compiler tools and the native language server report 0.99.3; the separately versioned VS Code extension is 0.2.0.

## Local control flow and immutable composition

Numeric and bool bindings can be reassigned without changing their type. Numeric and bool arrays support checked element mutation, replacement, and in-place sorting. Aliases retain their storage identity; replacing a binding does not replace an alias. Concurrent task readers and conflicting accesses remain compiler-checked. A scalar parameter is a private value: rebinding it does not modify its caller.

Use `copy(values)` for independent numeric, bool or String-array storage, `sorted(values)` for a sorted copy, and `sort(values)` to update existing numeric/bool storage. String text remains immutable. `generate` and `map` remain available for immutable array construction.

`for`, integer `range`, `while`, `break` and `continue` support ordinary iteration and early stopping. Loops can produce a single result with `break value` and an `else` result. `for`/`while` expressions containing `yield` instead construct lazy generators; consuming them runs their bodies, while `array(sequence)` explicitly materializes an array.

```kalandra
from "std/io" import println, IoError
from "std/fmt" import format

fn main() -> unit ! IoError:
  squares = for value in [0, 1, 2, 3, 4, 5]:
    if value % 2 == 0:
      yield value * value

  total: i64 = 0
  for value in squares:
    total = total + value

  try println(format("{}", total))
  return ()
```

This prints `20`. The generator produces 0, 4 and 16 as the consuming loop requests them.

## Iteration, generics and explicit traits

`Option[T]`, the uninhabited primitive `never`, reusable `Iterable` sources and owned `Iterator[T, E]` cursors provide typed iteration and error channels. `std/iter.map`, `filter` and `take` compose lazy pipelines. Breaking out of iteration closes its cursor; generator cleanup settles owned resources and cancels/joins unfinished children. Children may continue running while their generator is paused. Eligible local scalar pipelines are fused conservatively; escaping or effectful cursors retain their frames.

Static generics support generic functions/types, explicit `trait`/`impl` conformance, associated types/errors, qualified calls and generic trait parameters. Conformance is deliberate, not inferred from matching method names. Dispatch is static, with no user class hierarchy or runtime trait object.

Standard contracts include `Equal`; `Order`, `Ordering`, `compare` and `totalCompare`; stable `sortedBy`/`sortBy`; `Display`; and `Add[Rhs]`, `Sub[Rhs]`, `Mul[Rhs]`, `Div[Rhs]`, `Rem[Rhs]` and `Neg` with associated `Output`. Custom operators use ordinary evaluation, ownership and error rules. Implementing arithmetic does not grant mutation permission or automatically make a method GPU-compatible.

## Applications, files and host utilities

- **Application entry:** `main()` or `main(args: [String])` returns `unit` or `std/process.ExitStatus {code: u8}`. Arguments exclude the executable name. Function return values are not implicit console output; unhandled failures produce a nonzero process status.
- **`std/io`:** console output, error output and bounded line input, with typed `IoError` values.
- **`std/fmt`:** literal-template formatting, explicit `Display` implementations, checked fixed precision, alignment and integer hexadecimal controls. Width counts Unicode scalar values.
- **`std/fs`:** owned files, incremental byte/text/line I/O, buffered readers/writers, seeking, directory iterators, metadata, directory creation, and file/empty-directory removal. Handle cleanup and iterator early exit are deterministic. `finish` flushes and consumes a buffered writer.
- **`std/buffer`:** owned growable `ByteBuffer`, capacity management and array conversion. Filesystem `readInto`, `readAppend`, `write` and `writeAll` support buffers alongside their supported array forms.
- **`std/parse`:** checked parsing for all ten numeric primitives and bool, with typed failures and tested floating-point rounding behavior.
- **`std/path`, `std/env`, `std/time`:** path operations, environment lookup, monotonic `Instant`/`Duration` values and cancellable task sleep. Suspended sleep releases its worker.

These services run on the host, including in mixed CPU/Metal/Vulkan/CUDA programs. This release does not add OS subprocess spawning; `std/process` supplies application exit status.

## GPU language coverage

Metal, Linux Vulkan and Linux CUDA support the admitted local control flow, safe mutation and device-array construction, checked transfer of supported CPU closures/captures, and device-compatible typed error handling. GPU eligibility follows specialized method bodies and their supported values, effects and resource limits. Unsupported operations are diagnosed rather than silently executed on the CPU.

Host generators and I/O coexist with GPU work; suspended host cursor frames and host services are not device instructions. GPU string/text operations and user-written low-level kernels remain separate work. Existing numerical and matmul policies retain their documented contracts, including explicit software fallback where required.

Windows x86-64/ARM64 GPU packages remain **experimental**: build, source compilation, relocation and package checks pass, but physical Windows GPU execution/performance remains unqualified ([#276](https://github.com/kalandra-lang/kalandra/issues/276)). ARM64 compiler availability does not establish NVIDIA ARM64 driver support.

## Correctness, calls and tooling

Ordinary suspending function calls use task-local resumable call frames with a separate memory budget; they no longer consume task-admission slots merely for calling another function. Explicit tasks retain scheduler admission limits. Ownership, expected errors, faults, cancellation and child settlement are preserved across suspension and early return.

Buffer reuse after cancelled native file work now synchronizes with retired readers; live snapshots still trigger copy-on-write. Compiler type facts and capability prerequisites are centralized without adding runtime type-category dispatch.

Qualification includes native CPU execution across all 20 directed platform pairs, CPU/Metal sanitizer coverage where supported, and physical Linux CUDA/Vulkan correctness on RTX 5090. Vulkan Intel ASan/UBSan exits cleanly; NVIDIA retains the unsuppressed external loader/D-Bus leak tracked in [#298](https://github.com/kalandra-lang/kalandra/issues/298). A same-path pre-refactor control reproduces that leak; it is not reported as a clean NVIDIA LeakSanitizer pass. CUDA ASan/TSan, Vulkan TSan, Windows sanitizer limitations and cross-target sanitizer restrictions remain explicit.

The updated VS Code package and native language server cover the new keywords, primitives, traits, associated members and library APIs, including diagnostics, completion, hover, navigation, references, rename and formatting. Install the 0.2.0 VSIX from this release with the matching native server. Other LSP editors can use the same server over standard input/output; the installed native toolchain and VSIX do not need Node.js or npm.

## Migrate from 0.99.2

| Previous source or behavior | 0.99.3 |
| --- | --- |
| `int8`…`int64`, `uint8`…`uint64`, `float32`, `float64` | `i8`…`i64`, `u8`…`u64`, `f32`, `f64` |
| `int`, `uint`, `float` type aliases | Explicit `i64`, `u64`, `f64`, or another chosen width |
| `Bool` | `bool`; `unit` uses the literal `()` |
| Final expression implicitly returns a function result | Write `return value`, including in anonymous functions |
| Returning a value from `main` produces console output | Call `print`/`println` explicitly; return `unit` or `ExitStatus` |

Unconstrained integer/decimal literals still infer `i64`/`f64`. Larger types retain PascalCase. Unit functions may finish naturally, use bare `return`, or `return ()`. Expression-valued `if`, `match` and loops remain usable as operands, including after `return`.

Mutable function parameters use the explicit `mut` contract; owned resources use `own` where ownership transfers. Existing aliases and task readers constrain in-place writes. `copy` is an explicit storage copy, not a change to the meaning of assignment.

## Download and install

Choose your build host's package from this release's **Assets**, verify its SHA-256 sidecar and keep the complete directory together. Package names and platform baselines remain unchanged:

- macOS 26+ Apple silicon: `kalandra-native-metal-standalone.dmg` for CPU/Metal, with signed/notarized CPU-only and editor-only alternatives. Metal compilation requires Xcode 26.2 and the pinned Metal Toolchain component.
- Linux x86-64/ARM64: standalone CPU archives, glibc 2.39 or newer; modern Raspberry Pi systems use 64-bit Raspberry Pi OS Trixie. Linux x86-64 also provides CUDA and Vulkan archives.
- Windows 11 x86-64/ARM64: standalone CPU archives and experimental CUDA/Vulkan archives; use matching Visual Studio C++ tools and the Windows SDK.
- Install `kalandra-native.vsix` (extension 0.2.0) through **Extensions: Install from VSIX**, then select the release's `kalandra-lsp` using **Kalandra Native: Server Path**.

Standalone host packages carry private compiler/linker tools and CPU runtime data for all five supported CPU destinations. System development libraries and GPU drivers remain platform prerequisites. Cross-compilation covers CPU programs; GPU applications keep their complete PTX/SPIR-V resource directory. Installed CUDA compilers do not need the CUDA toolkit, NVRTC or cuBLAS; execution requires a compatible NVIDIA driver supporting PTX 9.2.

See [installation](https://kalandra.dev/docs/installation), [editor setup](https://kalandra.dev/docs/tooling), [language tutorial](https://kalandra.dev/docs/tutorial), [standard library](https://kalandra.dev/docs/library) and [GPU computing](https://kalandra.dev/docs/gpu).
