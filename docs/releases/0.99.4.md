# Kalandra 0.99.4 — cooperative GPU kernels, streams, networking and C interop

Kalandra 0.99.4 expands both GPU programming and practical host systems support: cooperative workgroup GPU kernels (`std/gpu`), UTF-8 text processing on GPUs, combined `--target cuda,vulkan` application bundles and release toolchains, byte streams and OS subprocesses (`std/stream` and `std/process`), recursive filesystem operations and directory watching (`std/fs`), event-driven TCP networking (`std/net`), checked C/C++ header imports and library exports (`export "C"`), and `-O0`–`-O3` optimization controls. It includes all changes merged since [0.99.3](https://github.com/kalandra-lang/kalandra/releases/tag/v0.99.3).

Compiler tools and the native language server report `0.99.4`; the separately versioned VS Code extension is `0.3.0`. Existing `0.99.3` programs require no syntax migration.

## Cooperative GPU kernels, GPU text and multi-backend bundles

`std/gpu` adds explicit workgroup dispatch across Metal, Vulkan and CUDA from one source representation:

- **`dispatch(outputShape, groupShape, fn(item: WorkItem) -> T)`:** launches fixed-size workgroups over rank 0–8 numeric output domains with checked coordinate queries (`globalIndex`, `localIndex`), scoped shared numeric scratch (`item.shared[T](count) -> Shared[T]`), and workgroup synchronization (`item.barrier()`).
- **Static safety proofs:** the compiler verifies barrier convergence across branches, helper calls and bounded loops, proves shared-memory initialization and non-overlapping lane writes before publication, and checks workgroup/shared-memory limits against the selected device without substituting CPU execution.
- **UTF-8 strings on GPUs:** functions spawned on Metal, Vulkan or CUDA now accept `String` values and read-only `[String]` batches (up to 16 KiB per row in cooperative kernels), supporting Unicode-scalar `length`, `byteLength`, scalar indexing, half-open `slice`, exact equality, concatenation, and variable-length owned `String` results returned to the host.
- **Combined CUDA + Vulkan builds (`--target cuda,vulkan`):** Linux and Windows releases now include `kalandra-native-gpu-standalone-<os>-<arch>.tar.gz` alongside the single-backend `cuda` and `vulkan` archives. Compiling with `kalandra main.k --target cuda,vulkan -O2 -o app` emits one application directory containing both PTX and SPIR-V artifacts; at runtime the first GPU request selects CUDA when a compatible NVIDIA driver is available and otherwise falls back to Vulkan, caching the admitted adapter for the process (`KALANDRA_GPU_BACKEND` and `KALANDRA_GPU_TRACE` override or inspect selection).

```kalandra
from "std/gpu" import dispatch, WorkItem
from "std/io" import println, IoError
from "std/fmt" import format

fn smooth(values: Tensor[f32, ?]) -> Tensor[f32, ?]:
  n = shape(values)[0]
  return dispatch([n], [256], fn(item: WorkItem) -> f32:
    i = item.globalIndex(0)
    lane = item.localIndex(0)
    tile = item.shared[f32](256)
    tile[lane] = if i < n: values[i] else: f32(0)
    item.barrier()
    left = if lane > 0: tile[lane - 1] else: tile[lane]
    return (left + tile[lane]) / f32(2)
  )

fn main() -> unit ! (TaskError | IoError):
  out = try parallel:
    gpu = devices.gpu()
    input = try await transfer(tensor([f32(2), f32(6), f32(10)]), gpu)
    res = try await spawn smooth(input) on gpu
    try await transfer(res, devices.cpu())
  items = array(out)
  try println(format("{} {} {}", items[0], items[1], items[2]))
  return ()
```

## Streams, subprocesses, filesystem watching and TCP networking

Host applications gain composable binary I/O traits, child-process management, recursive directory operations and asynchronous TCP sockets:

- **`std/stream`:** `ByteReader`, `ByteWriter` and `PipeCloser` traits with generic `readInto`, `readAppend`, `write`, `writeAll` and `close` over `ByteBuffer`, shared across files, buffered readers/writers, subprocess pipes and TCP sockets.
- **`std/process`:** `command`, `withDirectory`, `withEnv`, `withStdin`, `withStdout`, `withStderr`, `start`, `takeStdin`/`takeStdout`/`takeStderr`, cancellable `wait`, and bounded `capture(cmd, maxBytes)` with automatic termination/reaping when output exceeds `maxBytes` or an owning `Child` leaves scope.
- **`std/fs` recursive trees & watching:** `copyTree`, `removeTree`, symlink inspection/creation (`symlinkMetadata`, `readLink`, `createSymlink`), and owned `watchDir` event iterators backed by native OS notifications (`FSEvents`/kqueue on macOS, `inotify` on Linux, `ReadDirectoryChangesW` on Windows).
- **`std/net`:** `listenTcp`, `localPort`, `accept`, `connectTcp`, deadline-bounded `connectTcpWithin`, `shutdownWrite`, `setTimeout`, and `split` (`takeReader` / `takeWriter`) for concurrent full-duplex tasks. Bounded host resolution caps concurrent OS lookups and discards stale results on cancellation. Suspended socket waits release their worker thread and wake immediately via event-driven OS readiness (`kqueue` on macOS, `epoll` on Linux, `WSAPoll` on Windows).

```kalandra
from "std/net" import listenTcp, localPort, connectTcp, accept, shutdownWrite, NetError
from "std/stream" import readInto, writeAll, StreamError
from "std/buffer" import byteBuffer, append, BufferError
from "std/io" import println, IoError
from "std/fmt" import format

fn main() -> unit ! (NetError | StreamError | BufferError | IoError):
  listener = try listenTcp("127.0.0.1", 0)
  client = try connectTcp("127.0.0.1", try localPort(listener))
  server = try accept(listener)
  chunk = try byteBuffer(64)
  try append(chunk, [75, 97, 108, 97, 110, 100, 114, 97])
  try writeAll(client, chunk)
  try shutdownWrite(client)
  received = try readInto(server, chunk, 64)
  try println(format("{}", received))
  return ()
```

## Native C/C++ interop, CLI and editor tooling

- **C header imports & `export "C"` libraries:** import C declarations directly from headers using the target ABI, pass checked `noescape` or handle-scoped (`acquire_handle` / `release_handle` / `use_handle`) callbacks and scalar closures, enforce main-thread APIs (`@MainActor`), marshal fixed-width C structs and counted UTF-8 strings, and build static/shared/object libraries with generated C/C++ headers via `kalandra --emit static|shared|object --header out.h`. `export "C"` emits fault-checked status wrappers; `export "C" direct` emits direct C signatures when the compiler proves the body is context- and fault-free. See `native/examples/window` for a cross-platform AppKit/Win32/X11 GUI window written against one Kalandra entry point.
- **Optimization levels & CLI workflow:** `kalandra` now supports `-O0`, `-O1`, `-O2` and `-O3` while preserving checked arithmetic, ownership and cancellation; `--no-link` (paired with `--emit-mlir` or `--emit-llvm`) validates frontend checking, MLIR lowering and LLVM IR emission without object emission or host linking; `kalandra remove <alias>` removes direct manifest dependencies and prunes unreachable lock entries offline; and interactive terminal builds report phase progress with `--silent` and `--debug` controls.
- **Compiler, LSP & VS Code `0.3.0`:** fixes a semantic/LSP crash (`std::out_of_range`) when checking trait conformances alongside unrelated functions with broken signatures, adds `std/net` import-path completion in `kalandra-lsp`, adds `direct` declaration highlighting in VS Code `0.3.0`, and hardens Vulkan loader lifecycle teardown across repeated dispatches.

## Platform qualification and limits

Qualification covers native CPU execution across all 20 directed host/target pairs (`macOS ARM64`, `Linux x86-64/ARM64`, `Windows x86-64/ARM64`), 64-bit Raspberry Pi OS Trixie userspace, CPU/Metal sanitizers where supported, reproducible double-builds across all standalone archives, and physical Linux CUDA, Vulkan and combined `cuda,vulkan` execution on RTX 5090. The external NVIDIA EGL/Mesa Vulkan `LeakSanitizer` retention tracked in [#298](https://github.com/kalandra-lang/kalandra/issues/298) remains unchanged. Windows `x86-64` and `arm64` `cuda`, `vulkan` and combined `gpu` compiler archives pass build, relocation, PE-closure and installed-package checks and remain marked **experimental** (physical Windows GPU execution was exercised in an x86-64 RTX 5090 passthrough VM; broad hardware/ARM64 driver coverage remains tracked in [#276](https://github.com/kalandra-lang/kalandra/issues/276)).
