# Recursive value storage

Recursive records and enum payloads use compiler-managed references wherever a direct nominal field would otherwise create an infinite inline layout. Users keep ordinary immutable value syntax; there is no pointer, box, allocator or ownership annotation to write.

For example:

```kalandra
enum List:
  Nil
  Cons:
    head: int
    tail: List
```

Recursive CPU values are executable in ordinary functions and structured workers. Numeric/Bool/String fields, numeric arrays/tensors, Bool/String/record/enum arrays, callable fields and function arrays support construction, matching, projection, immutable updates and retained results. Local `spawn`/`await`, nested parallel groups, typed application-error channels, error-union widening/narrowing and recursive coordinating calls share the managed graph lifetime and scheduler budget. Compiler-managed references require no pointer or ownership syntax. GPU/distributed execution and public native embedding remain separate roadmaps.

## Storage decisions

The planner identifies strongly connected groups of nominal declarations twice: once including array element dependencies, and once with only directly embedded nominal fields. A direct field within an inline recursive group uses a managed reference. Other direct nominal fields retain their inline representation, except error-union forwarding: a nominal payload field uses a managed reference in every source/union carrier if any carrier requires boxing. This keeps widening and narrowing physically consistent without expanding a recursive graph.

Arrays already have a finite descriptor, so recursive array element types do not need an extra reference layer. For example, a tree containing `[Tree]` uses the ordinary array descriptor; its empty array is a finite base case. A cycle containing an array edge does not by itself require boxing the other direct fields.

Function signatures do not embed their parameter and result values. Their nominal references do not create storage edges. Existing function handles and other scalar/collection representations remain unchanged. These decisions make no public ABI or byte-size guarantee.

## Finite values

A record can be constructed when every direct nominal field can be constructed. An enum needs at least one variant with constructible payloads. Payload-free alternatives, primitive fields and empty arrays provide finite bases. The planner computes these facts with an iterative worklist, including mutual recursion and repeated dependencies.

`List.Nil` provides a base for `List.Cons`. In contrast, a record whose only field is another value of itself has no finite construction. Source checking rejects such unconstructible cycles with `S068`, rather than creating an implicit null or infinite value.

Values remain immutable. Construction can refer to existing values, rather than tying a recursive initialization knot. The intended runtime graph is therefore a finite directed acyclic graph with shared backing. A recursive type graph does not require cyclic runtime values.

## Ownership and admission

Managed payloads must retain immutable backing across construction, projection, matching, updates and returned values. Failure and cancellation must release partially constructed values. Releasing a deep graph must use an iterative, allocation-free worklist rather than recursive native destructors. Shared values must be released exactly once after their last owner disappears.

Physical type lowering follows a bounded dependency order with references and descriptors as leaves. Runtime nodes own explicit dependency references and use iterative final release. Cycle-safe retained-graph handoff registers complete immutable backing in receiving invocations for worker packets, continuation frames, cached outcomes, repeated awaits and typed error payloads. Scheduler-bound construction and retention reserve backing capacity before ownership publication.

## Implementation stages

1. **Implemented:** private storage planner with canonical recursive groups, per-field storage choices and finite-construction facts. Its graph traversal is iterative and bounded by a charged input budget. It validates nominal references and enum payload-slot partitions; it does not replace full typed-IR validation.
2. **Implemented:** ordinary field annotations resolve predeclared nominal identities without recursively expanding fields. Error aliases reserve stable identities before completed member payloads are copied, allowing finite cycles through aliases. The physical planner orders inline dependencies iteratively, bounds expanded scalar/pointer units and inline depth, and builds finite MLIR LLVM-dialect structures. The CPU backend uses this path for ordinary and qualified recursive programs. Invalid metadata and unsupported recursive payloads remain rejected.
3. **Implemented for the initial synchronous CPU subset:** checked constructors, field reads, branch-local pattern binding, immutable record updates and returned recursive values use managed backing. Recursive enum matches remain explicit in typed IR and lower to flat switches. Source and backend admission independently enforce the subset.
4. **Implemented for local CPU source:** cycle-safe worker packet/result retention, continuation frames, task-created closures, callable/record arrays, application-error payloads, family widening/narrowing and TaskError normalization use the shared storage plan. Managed nodes, ordinary buffers and ownership registrations participate in the scheduler byte limit. Nested source tasks, repeated awaits, recursive coordinating calls, finite error-union cycles, cancellation/deadlines, failure injection and budget boundaries have source/runtime qualification below.

GPU recursive values, distributed transport and public C/C++ representation are outside this step.

## Local handoff foundation

`Invocation::retainRecursiveGraph` is a private runtime operation for fully published immutable values. It accepts a retained root lease and the expected nominal token, byte size and alignment. A lease can outlive its producing invocation; receiving code does not access the producer's owner list or require that producer to remain executable.

Keeping the root alive alone is insufficient: checked field/collection/environment reads resolve addresses through the receiving invocation's ownership ledger. The handoff therefore walks all declared backing dependencies iteratively and registers each unique allocation, including array storage, recursive children, capture environments and their captured backing. Existing owners are reused, but their dependencies are still traversed, so a previously retained root cannot hide missing descendants. Duplicate graph edges preserve their original ownership while contributing only one receiving owner per backing. Payload bytes and pointers remain unchanged; this is local immutable sharing, not serialization or distributed transport.

The operation stages references without changing the receiving ledger. It publishes all owners only after validation, bounded traversal and a final cancellation check. Allocation failure, resource exhaustion or cancellation before that commit releases staged references and leaves existing owners intact. Cancellation racing with the final commit can observe a complete successful handoff; it never publishes a partial ledger. Workspace allocation exceptions become `AllocationFault`; faulted, settled and expected-error destinations are rejected while preserving their existing error state.

The initial private bound is 300,000 visited backing allocations, 300,000 traversed edges (including duplicates), and 300,000 total receiving owners. Traversal, rollback and final release use no recursive native calls. Temporary hash sets and worklists are bounded by these limits. Earlier reclamation, owner-index optimization and workspace compaction remain optimization work.

This retained-graph foundation is now used by source-level recursive workers, continuation frames, cached outcomes and typed errors. The final source integration and qualification appear below. GPU placement, distributed execution and public C/C++ representation remain separate work.

## Task-frame physical layouts

Task values keep the existing failure/payload/application-error wrappers, and pending task handles remain handles rather than expanding their result type.

## Task-frame field operations

The CPU continuation planner now represents ordinary record-field reads as explicit field instructions. `TaskRecordOps` lowers those instructions using the same `TaskValueTypes` physical fields as the frame. Preserved-call plans retain their previous kernel path, so this change does not add record support to Metal placement.

Every field operation checks invocation readiness, including cancellation, faults, settlement and invocation-held expected errors. Enum reads validate the full 64-bit discriminator and require the field's owning case before accessing its payload; inactive field projection produces a checked fault. Field-to-case identities are cached during physical planning rather than rediscovered by scanning every variant for each projection.

Inline fields load their completed physical value. Managed fields first validate the child reference's ownership, exact size/alignment and nominal token through the checked recursive read bridge, then load the completed child value. The task backend's aggregate-retention path likewise recognizes managed field storage and uses the retained-graph transfer bridge, instead of treating pointer slots as embedded records or recursively expanding direct type cycles. Copying retains the child's complete immutable backing graph; it does not mutate the source or execute stored functions.

Aggregate copies still enumerate only the active enum payload. A failed operation does not publish its output. Each managed-child transfer is transactional; if a later aggregate field fails, references acquired for earlier fields remain invocation-owned until ordinary failure cleanup. This is not immediate whole-aggregate rollback or last-use reclamation.

## Task-frame recursive record arrays

CPU task array retention now calls a generated helper for each nominal element type. Helpers are declared on first use and their bodies are emitted from a growing worklist. A self-recursive tree or mutually recursive record arrays therefore produce a finite set of functions rather than recursively expanding the compiler's retention emitter. Existing physical layouts, descriptor validation and active enum payload selection remain in use.

Each element helper enters the checked native call budget, checks invocation readiness and releases its call-depth entry on both success and failure. Nested arrays, including a malformed cyclic descriptor graph, stop when they exhaust the executing thread’s admitted physical stack. Array loops continue polling for cancellation. This is bounded runtime traversal, not an iterative graph-copy algorithm or unlimited-depth transport.

Non-callable array storage stays shared and immutable. The receiving invocation retains each array backing and the active element fields, including nested Strings and managed recursive children. Output is published only after the complete traversal succeeds. Earlier successful retains remain invocation-owned until cleanup if a later element fails. Ordinary array/String retains are not deduplicated: repeated observations acquire additional owners, released at invocation settlement. Sharing and reclamation optimizations remain separate work.

## Budgeted recursive graph handoff

Graph handoff now reserves retained backing against the scheduler's existing shared byte limit before publishing ownership. The charge includes each distinct reached allocation's private backing header, payload, padding, allocated dependency-table capacity, and one conservative receiving-owner allowance. Shared children and repeated imports reuse an existing charged ownership registration; a root previously registered through ordinary retention still contributes its backing and descendants. Null dependency slots contribute allocated table capacity even though they add no graph edges.

The handoff computes one checked byte total, stages references, and asks the receiving invocation's scheduler for a single reservation. Rejection produces an allocation fault without publishing owners or changing existing ownership registrations. Cancellation after reservation returns those bytes immediately and rolls back staged references. Execution and cached-outcome invocations both bind to the same scheduler budget, alongside fixed frame/result storage and existing environment reservations. `TaskStats::recursiveBytes` exposes this portion of retained bytes; peak bytes includes overlapping execution and result reservations.

Accounting is deliberately conservative and local to an invocation. Separate execution/outcome contexts each reserve shared backing; previously charged transport environments can also contribute to both accounting categories. Reservations last until invocation settlement, even if an owner is released earlier. Reacquiring backing after its charged registration is released can reserve it again. This is admission accounting, not a process-wide allocator measurement: temporary traversal workspace and allocator overhead are excluded, while existing graph node/edge/owner bounds remain enforced. Observers outside a scheduler track local graph bytes without retaining a pointer to the originating scheduler; their values remain usable after that scheduler is destroyed.

## Budgeted recursive node construction

Managed recursive node construction now reserves storage before allocation when its invocation is bound to a scheduler budget. This includes compiler-boxed closure environments and private dependency-owner nodes created by the same constructor. It uses the graph-handoff charge: physical backing header, padded payload, full allocated dependency-table capacity and one conservative owner allowance. Arithmetic overflow or exhausted shared capacity produces an allocation fault before storage is allocated or a node is published.

A temporary reservation owns the budget until construction commits. Allocation failure, cancellation, invalid dependency metadata or failure after retaining part of a dependency list releases the unpublished backing, rolls back retained edges and refunds the reservation. Successful construction attaches a charged ownership registration and keeps the reservation until invocation settlement. Later graph handoff within that invocation reuses the registration instead of charging the node again; dependencies not already charged still contribute their own storage. Returning the value to another invocation reserves that receiving context separately, preserving the existing conservative overlap policy.

[Runtime tests](../../native/tests/RecursiveHandoffTests.cpp) check exact and exhausted construction caps, dependency-table capacity, post-reservation cancellation, an exhausted second allocation, partial dependency rollback, settlement refunds and construction-to-handoff deduplication. [Generated entry tests](../../native/tests/RecursiveTaskEntryTests.cpp) run the production captured-closure factory in pools of one, two and four workers. A cap allowing only packet admission rejects subsequent environment creation; the exact successful peak accepts creation and cached-result transport, while one byte less fails without publishing a result. Successful closures retain their captures after their scheduler is destroyed. Debug, optimized, ASan/UBSan and TSan variants use the same checks. ## Budgeted ordinary backing allocation and retention

The shared scheduler byte limit now also admits ordinary task-local backing through `Invocation::allocate`, including String/array buffers, record storage and ordinary closure environments. It reserves the full physical backing header and payload plus one conservative owner allowance before allocating. `retainFrom` likewise reserves backing and owner capacity before allocating or publishing the receiving owner. Exhaustion and arithmetic overflow produce `AllocationFault`; cancellation immediately after reservation refunds it before ownership publication. Both operations reject unusable receiving contexts, and ordinary retention rejects an unusable source.

Ordinary retains each create a separate ownership registration, so each conservatively charges the backing again, including duplicate retains. Graph registration reuses surviving charged owners and does not recharge buffers allocated earlier in the same task. The private `recursiveBytes` counters now include these ordinary backing reservations as well as managed recursive storage. Reservations persist until invocation settlement even when explicit release or record cleanup removes an owner. Distinct task execution/result contexts can each reserve the same immutable backing. Transport-storage payload reservations and the existing environment cap remain additional conservative allowances.

## Managed runtime backing

The existing allocation backing now carries an optional immutable dependency list. Private `Invocation::makeRecursiveValue` copies a complete payload, retains existing dependency leases and publishes the node only after those operations finish. A stable compiler-generated type token identifies its physical payload. No mutable payload pointer is returned. This reuses invocation allocation, failure injection and retained leases rather than adding a separate heap or user-facing memory syntax.

The compiler bridge must enumerate every owned payload field, including recursive children and ordinary String/collection/function backing. The runtime retains the supplied dependencies; it does not discover pointer fields by inspecting arbitrary bytes. A private versioned runtime ABI and compiler emitter now implement the numeric/Bool/String bridge described below. The initial field enumeration and control-flow integration are source-qualified for numeric/Bool/String scalars, numeric collections, Bool/String/record/enum arrays, scalar function values and function arrays. Wider owned fields remain rejected until their enumeration and lifetimes are qualified. These are internal compiler/runtime symbols, not a public C/C++ or language API.

A retained lease can validate a recursive payload's type token, size and alignment, or independently retain one dependency by index. A returned byte view borrows its lease and must not outlive it. These operations continue to work after the original invocation settles. Dependency order is private metadata; it is not a source-level record layout guarantee. The private reference-count snapshot exists for diagnostics and ownership qualification, not synchronization or uniqueness decisions.

Parents retain children without duplicating their backing. Creating a different parent preserves the original value. Dependencies refer only to already-existing retained values, so this construction path cannot tie a mutable knot or introduce an ownership cycle. The invocation initially owns each published node and keeps its existing allocation lifetime; this step does not add last-use reclamation within an invocation.

Final release decrements child references using an intrusive worklist stored in retired backing headers. Only the thread retiring the final reference writes the worklist link. Cleanup allocates no memory and does not recurse on the native stack. Shared and duplicate edges each own a reference and retire independently. Cancellation or failure before publication destroys the temporary node and releases its acquired child references. Failure channels already present on an invocation are preserved.

[Runtime tests](../../native/tests/RecursiveValueRuntimeTests.cpp) exercise immutable copies, independent child projection, duplicate/shared tails, unchanged parents after replacement, ordinary backing dependencies, invalid construction/projection requests, injected allocation failure, cancellation races and concurrent retirement. A 100,000-link chain survives invocation settlement and releases on a 256 KiB thread stack; the retained terminal node's reference count verifies that the chain leaves no owned child edges behind. Debug, optimized, ASan/UBSan and TSan variants use the same cases. The same managed storage now participates in the source-worker path below.

## Compiler box/read bridge

[Recursive record operations](../../native/lib/RecursiveRecordOps.h) emit MLIR LLVM-dialect operations for publishing a complete nominal payload and reading it back. Constructors box fields selected by the storage planner; field access loads the checked aggregate behind those references. Immediate record validation stops at each managed reference instead of recursively generating an infinite type walk. Recursive storage also counts as managed backing for ordinary entry cleanup.

The initial emitter accepts numeric/Bool/String scalars, numeric arrays/tensors, Bool/String/record/enum arrays, inline records composed of those fields and managed recursive references. It also accepts synchronous scalar function fields and function arrays, and rejects other unsupported owned storage. It does not silently omit their backing. Extending this restriction is an implementation task, not a permanent language rule.

String fields contribute their immutable allocated buffer to the dependency table, including Strings inside inline nested records. The private `kalandra_recursive_string_dependency_v1` bridge validates active descriptors against invocation ownership and UTF-8 rules before publication. Canonical empty Strings contribute no backing. Inactive String slots are never inspected, validated or retained. The node retains the buffer without copying its bytes; it still copies the fixed-size descriptor as part of its payload. Ordinary String operations retain their existing allocation behavior.

Numeric collection fields contribute their validated allocated buffer through `kalandra_recursive_tensor_dependency_v1`. It reuses the existing ranked descriptor validator: owned base, zero offset, contiguous strides, checked sizes, alignment and byte capacity. Numeric rank-zero, fixed/dynamic shapes and zero-count shapes follow the existing collection rules. Bool arrays use `kalandra_recursive_bool_dependency_v1`, which also validates that each byte is zero or one. Inactive collection slots are ignored without reading descriptor contents; canonical empty buffers contribute no dependency. Boxing retains these buffers without copying their contents. Existing construction and numeric field-read copies remain unchanged; shared-storage optimization is still separate work.

String arrays use `kalandra_recursive_string_array_dependency_v1` to create a private immutable owner for the descriptor array and every nonempty String buffer. The bridge validates the complete array and its Strings before collecting dependencies. Shared/duplicate String buffers keep one retained edge per element; empty Strings have no buffer edge. Empty arrays contribute no owner. Inactive fields are neither inspected nor allocated. The parent node retains this owner through the same managed dependency mechanism, so array descriptors and character bytes survive together after invocation settlement.

The bridge uses a bounded temporary pointer table and a managed owner node; it releases the table on success, fault or cancellation. Neither the array contents nor String bytes are copied by this step. The owner retains a copy of the small array descriptor. The current private limit is 300,000 dependencies per owner: one descriptor buffer plus at most 299,999 nonempty String element buffers, counting duplicates. Exceeding that limit produces `AllocationFault`. This is an implementation resource bound, not a permanent language rule. Combining the temporary table and owner allocation, and compacting duplicate edges, remain optimization work.

Record and enum arrays use `kalandra_recursive_record_array_dependency_v1` and compiler-generated element helpers. The bridge validates contiguous descriptor storage before any cell load, retains the array backing, invokes the checked helper for each element and retains the resulting element owner. Helpers validate enum tags, retain only active fields, check managed references against their nominal token/layout, and recursively collect nested array/String/numeric/Bool backing. Equal or shared element buffers retain independent edges; their bytes remain immutable.

Element helpers are declared first and generated through a work queue, so array-mediated type cycles do not recursively expand the compiler's own stack. This supports trees containing `[Tree]`, mutually recursive record/enum arrays and arrays of direct-recursive values. The literal storage-budget calculation is also iterative and treats managed references and collection descriptors as leaves. Source and backend independently retain their existing literal expansion limits.

Each nonempty record/enum array owner currently allocates a temporary pointer table, one boxed ownership aggregate per element, and one array owner. The original array backing and its elements' owned buffers are retained; each element owner copies its fixed aggregate payload. The temporary table is released on success, cancellation or failure. The limit is 299,999 elements per array owner plus one descriptor backing edge; exceeding it produces `AllocationFault`. Recursive element helpers use checked call admission, so deeply nested ownership traversal can produce `StackExhaustionFault` even when the source function itself does not recurse. Heap-stack traversal, memoizing repeated shared subgraphs and reducing element-owner copies/allocations remain optimization work. This step does not add worker transport or a public callback/FFI interface.

Scalar function fields store the existing private code/environment pair. Capture-free entries have no environment dependency. Captured functions in recursive compilation units now use a managed environment node: the compiler describes captures through internal layout records and boxes them using the same String/collection/record/function dependency enumeration as ordinary recursive values. Nested closures retain their captured environments transitively; returning a containing record or array keeps those edges intact. These internal records introduce no source declarations or ownership syntax.

`kalandra_recursive_environment_bind_v1` binds a newly created environment to its compiler-owned code entry before the function pair is published, and rejects rebinding. Function-field enumeration validates the active code/environment pair and retains its environment. Inactive fields are ignored. Captured callable entry wrappers check the environment's owned backing, exact payload size and code identity through `kalandra_recursive_environment_read_v1` before loading it. Ordinary acyclic programs retain their existing environment allocation path. These are private compiler entrypoints; they do not validate arbitrary foreign code pointers or expose a public callback ABI.

The synchronous subset includes named functions, anonymous captures, nested captured functions, recursive record/collection captures, callable fields in record arrays, and signatures using nominal recursive arguments/results. Fallible CPU callable signatures and error control are now integrated; device capabilities remain excluded. Stored function signatures do not create nominal storage edges. Existing code-generation, signature, allocation and checked-call budgets remain in force. A retained backing lease can preserve environment bytes after its creating invocation settles; invoking that function still requires a valid execution context and does not establish worker transport or invocation reuse after settlement.

Function arrays use `kalandra_recursive_function_array_dependency_v1`. It validates contiguous descriptor storage and every active code/environment pair before publishing an owner. That owner retains the array backing and each nonnull managed environment, including one edge per duplicate. Captured function arrays use the same path inside managed closure environments. Array contents and capture payloads are not copied by this bridge.

The temporary pointer table is released on success or failure. The private 300,000-dependency limit counts one array buffer plus up to 299,999 nonnull environments, including duplicates; capture-free elements do not consume environment edges. Exceeding it produces `AllocationFault`. Code entries remain trusted compiler output, not arbitrary foreign callback addresses. Recursive worker and error-channel support is qualified by the final source suite below.

Dependency enumeration follows inline fields iteratively with a work budget and cached variant-slot identities. Only active enum payloads contribute references. Inactive slots become null entries in the compiler's temporary dependency table; the runtime ignores those entries. Duplicate non-null entries each retain an edge. Payload and table storage use fixed function-entry stack slots, avoiding repeated stack allocation when the operation is emitted inside a loop.

`kalandra_recursive_make_v1` verifies request metadata and resolves non-null dependency pointers through the current invocation's allocation ledger, without dereferencing unknown pointers. It reuses the existing construction transaction. `kalandra_recursive_read_v1` checks ownership, nominal token, size and alignment before permitting a load. Compiler-generated tokens have distinct addresses even for equal physical layouts. The checked invocation ABI polls after either call and exits before a load/store when allocation fails, a reference is invalid or execution is cancelled. These borrowed reads rely on the invocation retaining its published nodes; they do not establish a public raw-pointer ownership convention.

[Emitter tests](../../native/tests/RecursiveRecordEmitterTests.cpp) generate and verify MLIR and checked LLVM IR. [Compiled bridge tests](../../native/tests/RecursiveRecordBridgeTests.cpp) link that emitted LLVM code against the runtime in Debug, optimized, ASan/UBSan and TSan builds. They exercise boxed constructors, shared children, replacement parents preserving their originals, nested inline records, inactive payloads containing invalid pointer bits, allocation failure at every publication, wrong nominal tokens and unknown references rejected before a load. Raw bridge cases also check foreign dependencies, invalid tables, partial-retain rollback and projection metadata.
